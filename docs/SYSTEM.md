# ЛИЧНЫЙ БРЕНД — СИСТЕМА ПРОИЗВОДСТВА КОНТЕНТА
Фархат Романов. Версия 1.0 · одна система на весь личный бренд, не на каждый бизнес.

---

## 1. СТАТУСЫ РОЛИКА

Один ролик живёт в одном статусе. Статус хранится только в базе (Supabase), больше нигде не дублируется.

| Статус | Что значит | Что запускает дальше |
|---|---|---|
| `inbox` | идея/референс залетел в Telegram | мой разбор |
| `script` | сценарий написан, жду утверждения | кнопка «Ок» в боте |
| `ready` | утверждён, текст суфлёра собран | партия на съёмку |
| `shot` | снят, исходники выгружены | монтаж |
| `edit` | в монтаже | проверка |
| `done` | готовое видео лежит в 05_Готово | публикация |
| `published` | опубликован, ссылка сохранена | разбор через 7 дней |
| `dropped` | отказались от идеи | — |

## 2. ID И НАЗВАНИЯ ФАЙЛОВ

**ID ролика:** `ГГММ-NN` → `2610-07` (седьмой ролик октября 2026). ID не меняется никогда.

**Партия съёмки:** `ГГГГ-ММ-B1` → `2026-10-B1`.

**Файлы:**


**Правило актуальной версии:** актуальна версия с максимальным `v`. В суфлёр уходит только файл со статусом `ready` — старые версии физически не попадают в папку съёмки.

**Метки (теги), а не отдельные папки:** `#ai` `#aitrend` `#trendlenta` `#brandtrend` `#starlink` `#story` `#case` `#demo` `#kz` `#ru`

## 5. ТЕКСТ СУФЛЁРА — ФОРМАТ

Файл `_prompter.txt`. Внутри **только то, что я произношу**. Никаких ремарок, таймкодов, пометок монтажа.

Правила:
- строка = 5–8 слов;
- абзац = одна мысль, между абзацами пустая строка (это пауза);
- цифры словами, если короткие: «три года», а не «3 года»;
- никаких скобок и символов, которые я случайно прочитаю.

Пример:

```
Я три года строил отдел продаж.

И каждый раз ломался на одном месте.

Сейчас покажу, где именно.
```

## 6. ПОРЯДОК ПАРТИИ (день съёмки)

1. Все тексты партии утверждены заранее. Неутверждённые не снимаем.
2. Бот отдаёт один файл с порядком роликов и отдельные тексты суфлёра.
3. Перед каждым роликом вслух: «ID 2610-07, дубль один».
4. Хороший дубль — хлопок в ладоши после фразы. На монтаже видно по волне.
5. После партии: выгрузка в `03_Исходники/<партия>/`, переименование по ID, статус `shot`.

## 8. ПРАВИЛА СЦЕНАРИЯ (stop-scroll + AIDA)

**Структуры** (в базе `brand_frameworks`, Claude выбирает одну при сборке пакета):
AIDA-60 · PAS-45 · Хук → Раскрытие → Петля · Кейс с цифрой · История (момент → поворот → цена → урок) · Демо за 60 секунд.

**Правила речи** (в базе `brand_voice`, попадают в каждый запрос к Claude):
- хук в первые 1–2 секунды, без приветствий;
- хук = обещание, тело обязано его выполнить;
- 2,5–3 слова/сек → 60 сек = 150–180 слов, проверка чтением вслух;
- предложение до 12 слов, разговорная речь;
- конкретика: цифры, названия бизнесов, места в Алматы;
- смена кадра / вставка / текст на экране каждые 10–15 сек;
- один CTA, подготовленный одной фразой в середине;
- текст на экране в первые 3 сек — одна строка, крупно, дублирует хук;
- последняя строка пишется первой и замыкает на хук;
- казахский — живой, не перевод.

**NERV-проверка хука:** новизна, эмоция, релевантность, недосказанность — по 1–5. Меньше 12/20 — переписать начало. Claude ставит оценки автоматически при сборке пакета.

**Библиотека хуков:** 32 формулы, 10 категорий (`contrast`, `number`, `curiosity`, `story`, `mistake`, `demo`, `local`, `interrupt`, `stakes`, `identity`, `proof`), каждая с примером RU и KZ.
